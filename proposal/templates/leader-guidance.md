# リーダー向けガイダンス資料

> チームメンバーの資料ブラッシュアップを支援するためのガイド

---

## このガイダンスでわかること

1. イベントの目的と評価基準
2. リーダーとして何をすればいいか
3. フィードバックの進め方
4. よくある質問と回答

---

## 1. イベントの目的

このイベントは「誰が一番成績が良いか」を決めるためではありません。

**目的：プロセスにこだわる働き方を社内に広げる**

```
評価のポイント（優先順位順）

1位 プロセス（50点）
   どう取り組んだか、なぜそのやり方を選んだか、
   困難にどう向き合ったか、何を学んだか

2位 付加価値（30点）
   何を生み出したか、誰の役に立ったか

3位 歴史変容（20点）
   会社の29年の歴史との接点、変化への関与
```

**リーダーへのお願い：**  
採点者にならなくていいです。「引き出し役」になってください。

## 3. チームキックオフの進め方（7月5日）

### アジェンダ（60分）

```
0:00〜0:10  イベントの目的と評価基準の説明
            └─ 「プロセスが最も大事」を全員で確認
            └─ ルーブリック（採点基準）を簡単に説明

0:10〜0:25  参加者自己紹介
            └─ 名前・部門・「今年どんな仕事をしたか一言」

0:25〜0:50  ミニワーク：「今年一番困ったこと」を書いてみる
            └─ 各自5分で1枚に書く
            └─ チームで共有（採点しない、聞くだけ）
            └─ 「それ、もっと教えて」と質問し合う

0:50〜1:00  スケジュール確認＆質疑応答
```

### キックオフで伝える大事なこと

```
① 完璧な資料を目指さなくていい
  「自分の仕事を正直に語った資料」が評価される

② 結果が悪かった年でも参加できる
  プロセスを丁寧にやった経験は、成果に関係なく価値がある

③ 一人で頑張らない
  チームでブラッシュアップするための場がある
```

## 4. フィードバックの進め方

### フィードバックの「型」

```
① まず「良い点」を伝える
  「このエピソードが一番伝わった」
  「ここのプロセス説明、具体的で良かった」

② 「もっと聞きたい」質問をする
  「そのとき他にどんな選択肢があった？」
  「なぜそのやり方を選んだの？」
  「その困難で何を一番学んだ？」

③ 改善提案は「こう見える」で伝える
  「ここ、もう少し具体例があると伝わりやすそう」
  「プロセスのページをもう1枚増やせる？」

④ 最終判断は本人に任せる
  「あとは◯◯さんが判断して」
```

### フィードバック用チェックポイント

プロセスの評価に関して確認すること：

```
□ 仕事の「段取り・計画」が具体的に書かれているか？
□ 「困難だったこと」が具体的に書かれているか？
□ 「どう乗り越えたか」のプロセスが書かれているか？
□ そこから何を学んだか（改善）が書かれているか？
□ 自分なりの「工夫・創意」が伝わるか？

付加価値について：
□ 成果が（できれば数字で）書かれているか？
□ 誰の役に立ったか具体的か？

全体について：
□ スライドは 8〜12ページ？
□ 音声は 3〜5分？
□ 1ページのテキストが多すぎない？（150字以内目安）
```

## 5. よくある質問（リーダー向け）

**Q: メンバーがドラフトを出してこない場合は？**  
A: 「完成させなくていいから1枚だけ送って」と声をかけてください。ハードルを下げることが大事です。

**Q: どの程度まで手伝っていいか？**  
A: 「こう書いて」はNG。「こう聞こえる」「こういう質問が浮かんだ」はOK。本人の言葉で書かれていることが重要です。

**Q: チームで会う時間が取れない場合は？**  
A: 非同期でもOK。GoogleドキュメントやSlack/チャットでコメントを送り合うだけでも十分です。

**Q: メンバーが「提出したくない」と言ったら？**  
A: 強制ではありません。ただ「どうしてそう感じる？」と理由を聞いてみてください。「完璧でないと出せない」という心理的ハードルが多い場合があります。

**Q: 自分も参加者の場合、利益相反は？**  
A: リーダー自身も参加者として資料を出せます。チームメンバーの資料には採点者としては関与しません（実行委員会が採点担当者を別途アサインします）。
