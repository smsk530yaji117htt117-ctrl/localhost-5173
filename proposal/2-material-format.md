# 2. 資料提出フォーマット標準化

> 1,000人分の資料を公平に評価するために、フォーマットを統一する

---

## 2.1 なぜ標準化が必要か

フォーマット自由の問題点：
- 評者が「資料の上手さ」で判断してしまう（デザイン力への評価バイアス）
- 必要な情報が抜け落ちた資料が大量発生
- 評者ごとに読み取りにかかる時間が大きく異なる

**フォーマット統一の効果**: 全員が同じ土俵で評価され、プロセス・内容そのものが評価される

---

## 2.2 Googleスライドテンプレート仕様

### 基本仕様

| 項目 | 仕様 |
|-----|------|
| フォーマット | Google スライド（共有リンク提出） or .pptx |
| ページ数 | **8〜12ページ**（厳守） |
| フォント | 本文 18pt 以上（読みやすさ確保） |
| 1ページのテキスト量 | 150字以内を目安 |
| 画像・グラフ | 積極的に活用可（1ページ1〜2点まで） |
| 言語 | 日本語 |

### スライド構成（8〜12ページ）

```
【必須ページ】
Page 1  ── タイトルページ
              氏名／部門／職位／対象期間

Page 2  ── 仕事の全体像（概要）
              どんな仕事に取り組んだか（200字以内）

Page 3-4 ── プロセス①：段取り・計画（最重要）
              └─ どう計画したか
              └─ 計画のどこがこだわりだったか

Page 5-6 ── プロセス②：困難と対処（最重要）
              └─ 何が難しかったか（具体的に）
              └─ どのように乗り越えたか
              └─ 何を学んだか

Page 7   ── 付加価値：成果・貢献
              └─ 数値でわかる成果
              └─ 組織・顧客への貢献

Page 8   ── 歴史変容：会社との接点
              └─ この仕事が会社の29年の歴史とどうつながるか
              └─ どんな変化を起こしたか

【任意ページ（最大4ページまで）】
Page 9-12 ── 補足資料、データ、写真 等
```

## 2.3 音声ファイル仕様

| 項目 | 仕様 |
|-----|------|
| 形式 | MP3 / M4A / WAV （いずれか） |
| 録音時間 | **3〜5分**（厳守） |
| 内容 | スライドに沿ったプレゼンテーション |
| 推奨品質 | 静かな環境でクリアに録音 |
| ファイルサイズ | 50MB以内 |
| 提出方法 | Googleドライブへのリンク |

### 音声録音のコツ

```
✓ スライドを見ながら話すように録音する
✓ 結論（一番伝えたいこと）を冒頭30秒で話す
✓ 数字・具体例を使って話す（「たくさん」より「3件」）
✓ プロセスの説明に全体の半分以上を使う
✓ 全力プレゼンよりも「聞きやすさ」を優先
```

## 2.4 提出フォーム設計（Google フォーム）

### フォームの構成

```
【セクション 1】基本情報（必須）
  ├─ 氏名（記述）
  ├─ 所属部門（プルダウン）
  ├─ 職位（プルダウン）
  └─ 所属チーム名（5〜6名のチーム）（記述）

【セクション 2】資料提出（必須）
  ├─ Googleスライドの共有リンク（URL入力）
  │   └─ 注意書き：「リンクを知っている全員が閲覧可能」に設定してください
  └─ 音声ファイルのGoogleドライブリンク（URL入力）
      └─ 注意書き：「リンクを知っている全員が閲覧可能」に設定してください

【セクション 3】自己採点（任意）
  ├─ プロセス軸：自分の点数は？（1〜5のスケール）
  ├─ 付加価値軸：自分の点数は？（1〜5のスケール）
  └─ 一番伝えたいことを一言で（100字以内）

【セクション 4】確認事項（必須）
  ├─ チェック：「上記の資料は私自身の仕事に基づいたものです」
  └─ チェック：「評価結果の利用に同意します」
```

### Googleフォーム設定のポイント

```
✓ 回答者のGmailアドレスを記録する（重複チェック用）
✓ 提出完了後に自動確認メールを送信する
✓ タイムスタンプを記録する（提出時刻の把握）
✓ 提出期限後はフォームを自動クローズする設定
✓ 1人1回の提出に制限する
```

## 2.6 ファイル命名規則

### 命名フォーマット

```
【スライド】
{参加者ID}_{氏名}_{提出日}.pptx
例：0042_山田太郎_20260712.pptx

【音声】
{参加者ID}_{氏名}_audio_{提出日}.mp3
例：0042_山田太郎_audio_20260712.mp3
```

> 参加者IDは提出フォーム送信時に自動採番（スプレッドシートの行番号を使用）

## 2.7 提出要領（参加者向け配布資料）

```
━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━
  ロマンある働き方 評価イベント 2026
  資料提出要領
━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━

【提出期限】2026年7月12日（土）17:00

【提出物】
  ① Googleスライド（8〜12ページ）
  ② 音声ファイル（3〜5分）

【提出方法】
  Googleフォームから提出してください
  → フォームURL：（別途案内）

【スライド構成】
  1ページ目  ：タイトル（氏名・部門・職位）
  2ページ目  ：仕事の全体像
  3〜6ページ目：プロセス（段取り・困難・対処・学習）← 最重要！
  7ページ目  ：成果・付加価値
  8ページ目  ：歴史変容（会社とのつながり）
  9〜12ページ目：補足資料（任意）

【評価の重点】
  プロセス（50点）> 付加価値（30点）> 歴史変容（20点）
  
  結果よりも「どうやったか」「なぜそのアプローチを選んだか」
  「困難をどう乗り越えたか」を重視します。

【よくある質問】
  Q: 資料のデザインを凝る必要はある？
  A: いいえ。内容・プロセスを重視します。シンプルで読みやすい資料が理想です。

  Q: 成果が数字で出ていない場合は？
  A: 定性的な貢献（チームの雰囲気改善、後輩の成長 など）も評価対象です。

  Q: チームで取り組んだ成果でもいい？
  A: 自分が担った役割・行動を具体的に記述してください。

━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━
```
